## 2. 本次目标

使用独立测试介质验证 Paragon 写入与 Linux 复核流程，生成可追溯的测试报告，不触碰真实 Ubuntu 系统分区。

## 3. 具体开发要求（顺序执行）

1. 先实现**测试计划与设备核验页**：展示物理磁盘号、分区 GUID、容量、卷标、挂载路径，明确判定非系统磁盘、非 EFI/MSR/Recovery、非 Ubuntu 真实分区。
2. 设备不明确、用户未明确确认、没有可用独立测试介质时，只输出验证清单并停在任务 07，不执行任何写操作。
3. 在用户明确批准且独立介质合规时，通过 Paragon 挂载的标准文件 API 测试：新建小文件、修改内容、创建目录、重命名、复制、删除指定测试内容，记录 SHA-256。
4. 对每项操作记录 Linux 权限/UID/GID、可执行位、大小写、符号链接处理差异；不假设 Windows API 能保持 Linux 元数据。
5. 测试只允许在测试介质下由应用新建的指定目录；默认不提供格式化操作，不删除用户预存文件。
6. Windows 端正常关闭文件并卸载测试介质后，在 Linux 挂载验证：数据、目录结构、UID/GID、权限/符号链接；必要时对**已卸载的测试文件系统**运行只读 `e2fsck -fn` 做检查（只读诊断输出仍需审查）。
7. 完成多轮验证并保存日志与验收记录。任何错误均保持真实 Ubuntu 写入 gate 关闭；不得为了通过测试而修改真实 Ubuntu 的 ext4 特性。
8. 将通过测试的**驱动版本+设备/文件系统特性指纹+测试条件**记录为兼容性证据，但不能把它等同真实 Ubuntu 分区的最终许可。

## 5. 测试方法

- 自动化测试先用 mock/临时目录验证写流程，但报告必须严格区分“模拟测试通过”和“独立 ext4 实际写入通过”。
- 实物测试需要用户现场参与：Windows 写入、正常卸载、Ubuntu 读取、内容哈希与元数据核验。
- 观察异常：断开设备、权限拒绝、目标空间不足、路径被切换；不可用时安全退出。

测试启动前必须向用户显示目标设备身份和允许写入目录，并获得**本次明确授权**；如果缺少授权，只生成文档和离线模拟测试，不执行写入。

## 全任务统一安全要求

1. 严禁执行 `format`、`diskpart clean`、`Clear-Disk`、`Remove-Partition`、`Set-Partition`、`Set-Disk -IsOffline` 或任何修改分区表/EFI/Recovery/MSR 的命令；不直接开启 `\\.\PhysicalDrive0` 写句柄。
2. 默认禁止对 Ubuntu 分区 6 做任何文件创建、覆盖、删除、移动或属性修改；只有任务 08 在任务 07 实际通过、备份完成、明确授权且限定范围时才例外。
3. 对驱动、分区身份、权限或实际挂载模式存在疑问时，结果为 `UNKNOWN` 或 `READ_ONLY`，不推测具备写权限。
4. 除任务 05 在用户授权的 Windows 专用测试目录、任务 07 在独立可丢弃 ext4 测试介质、任务 08 在额外明确授权的 Ubuntu 专用测试目录外，真实磁盘只允许元数据查询和只读操作；自动化单元测试优先使用 `TemporaryDirectory` 或模拟适配器。
5. 不自动提升管理员权限；不能通过 `os.access`、磁盘类型、盘符、Windows 卷标志或人工关联推断 ext4 写入安全性。
6. 任何可能改变 Windows 文件的功能，必须在用户指定的测试目录中测试；禁止自动对真实个人文件进行 CRUD 测试。
7. 每次开发前检查 Git 状态并保留当前可用版本。若项目未初始化 Git，先征询用户或在项目目录内初始化；不得强制覆盖、重置或清理其未提交修改。
