## 2. 本次目标

建立可审计的 Paragon 驱动接入层和 ext4 写入资格判定框架，但本任务绝对不启用真实 ext4 写入。

## 3. 具体开发要求（顺序执行）

1. 新建 `Ext4MountedAdapter`，基于经验证的已挂载路径复用 Windows 文件 API **只读** 操作。保留 `ReadOnlyMountedAdapter` 作为安全后备。
2. 分离三个概念：`filesystem_identity`（卷是何种文件系统）、`mount_access_observation`（当前会话报告的挂载能力）、`policy_write_authorization`（本软件是否允许写）。
3. Paragon 检测只报告可确认的信息，如挂载卷可访问、可能的文件系统名称；驱动版本、许可和当前 R/W 模式若无法通过稳定 API 验证，必须显示“未知”。
4. 设计 `Ext4WriteGate`，条件须包括受信分区身份、文件系统特性兼容声明、当前挂载模式被可信确认、独立介质测试通过、实盘测试授权和允许写的路径范围。初始所有条件为假。
5. 增加只读诊断页面/报告，可导出诊断 JSON（Windows 本地目标），不得把“E: 可在资源管理器打开”解释为可写。
6. 文档明确商业驱动为外部依赖，禁止未经授权随 EXE 分发；兼容性不确定的特性（如 `metadata_csum`）必须单独验证。
7. 在测试中模拟“驱动缺失、挂载只读、状态未知、错误关联、读写声明”并保证本任务写操作始终拒绝。

## 5. 测试方法

- 单测验证所有 gate 初始为关闭，手工关联/卷只读标志 False/进程管理员不触发 ext4 写入。
- Windows 本机仅检查 E: 的目录与诊断状态；不创建任何 E: 文件。
- Paragon 被卸载或 E: 不挂载时，软件正常降级为 Windows 卷管理。

项目根目录的通用测试命令：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -p "test_*.py" -v
.\.venv\Scripts\python.exe .\main.py
```

新增测试需纳入统一 discovery；如果引入 `tests/` 包，确认 discover 能正确发现。

1. 严禁执行 `format`、`diskpart clean`、`Clear-Disk`、`Remove-Partition`、`Set-Partition`、`Set-Disk -IsOffline` 或任何修改分区表/EFI/Recovery/MSR 的命令；不直接开启 `\\.\PhysicalDrive0` 写句柄。
2. 默认禁止对 Ubuntu 分区 6 做任何文件创建、覆盖、删除、移动或属性修改；只有任务 08 在任务 07 实际通过、备份完成、明确授权且限定范围时才例外。
3. 对驱动、分区身份、权限或实际挂载模式存在疑问时，结果为 `UNKNOWN` 或 `READ_ONLY`，不推测具备写权限。
4. 除任务 05 在用户授权的 Windows 专用测试目录、任务 07 在独立可丢弃 ext4 测试介质、任务 08 在额外明确授权的 Ubuntu 专用测试目录外，真实磁盘只允许元数据查询和只读操作；自动化单元测试优先使用 `TemporaryDirectory` 或模拟适配器。
5. 不自动提升管理员权限；不能通过 `os.access`、磁盘类型、盘符、Windows 卷标志或人工关联推断 ext4 写入安全性。
6. 任何可能改变 Windows 文件的功能，必须在用户指定的测试目录中测试；禁止自动对真实个人文件进行 CRUD 测试。
7. 每次开发前检查 Git 状态并保留当前可用版本。若项目未初始化 Git，先征询用户或在项目目录内初始化；不得强制覆盖、重置或清理其未提交修改。
