## 2. 本次目标

整合文件操作权限与安全逻辑；让正常卷的 CRUD、复制搜索在异常下稳定运行；决定 V1.0 是否能开放 ext4 受控写入。

## 3. 具体开发要求（顺序执行）

1. 将 UI 所有写入口统一调用 `WritePolicy`，后端方法再次检查；不得仅靠按钮禁用保护系统分区。
2. 将卷身份、路径允许范围、只读/未知、挂载变化、权限、空闲空间、已有文件冲突、符号链接重定向等检查集中在执行前并在提交前复核。
3. 补充不可逆操作确认与备份策略；删除优先回收站，批量删除展示操作数、总大小和目标；跨分区移动采用复制→校验→独立询问→删源流程，失败保留源。
4. 任务取消、盘符拔出、驱动进程异常、权限拒绝、写满、同名冲突、文本保存中途失败等应提供可理解的错误并尽量不丢失原数据。
5. 日志脱敏：默认不记录文件内容、密钥、密码；只记录必要路径、阶段、错误代码、关联证据和动作结果；合理限制日志大小。
6. 性能优化：大目录分页/延迟加载、搜索取消时延、复制限速可选、UI 卡顿指标、PySide6 worker 线程生命周期。
7. 对 ext4 写能力按任务 08 的实际状态决定：若 BLOCKED，GUI 必须继续保持只读并将该功能标记“未通过验证”；若 PASS，仍需每次会话显式解锁和受控范围。
8. 补齐集成回归矩阵与用户操作说明，为最终 EXE 打包做准备。

## 7. 本次禁止事项

不得为了减少提示而降低 ext4 gate；不得把不可恢复的操作描述成可撤销；不得对用户系统目录自动压测。

## 全任务统一安全要求

1. 严禁执行 `format`、`diskpart clean`、`Clear-Disk`、`Remove-Partition`、`Set-Partition`、`Set-Disk -IsOffline` 或任何修改分区表/EFI/Recovery/MSR 的命令；不直接开启 `\\.\PhysicalDrive0` 写句柄。
2. 默认禁止对 Ubuntu 分区 6 做任何文件创建、覆盖、删除、移动或属性修改；只有任务 08 在任务 07 实际通过、备份完成、明确授权且限定范围时才例外。
3. 对驱动、分区身份、权限或实际挂载模式存在疑问时，结果为 `UNKNOWN` 或 `READ_ONLY`，不推测具备写权限。
4. 除任务 05 在用户授权的 Windows 专用测试目录、任务 07 在独立可丢弃 ext4 测试介质、任务 08 在额外明确授权的 Ubuntu 专用测试目录外，真实磁盘只允许元数据查询和只读操作；自动化单元测试优先使用 `TemporaryDirectory` 或模拟适配器。
5. 不自动提升管理员权限；不能通过 `os.access`、磁盘类型、盘符、Windows 卷标志或人工关联推断 ext4 写入安全性。
6. 任何可能改变 Windows 文件的功能，必须在用户指定的测试目录中测试；禁止自动对真实个人文件进行 CRUD 测试。
7. 每次开发前检查 Git 状态并保留当前可用版本。若项目未初始化 Git，先征询用户或在项目目录内初始化；不得强制覆盖、重置或清理其未提交修改。
