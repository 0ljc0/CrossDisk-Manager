## 2. 本次目标

实现具有实用价值的 Windows 风格只读文件管理界面，所有文件浏览均通过上一任务的访问模型。

## 3. 具体开发要求（顺序执行）

1. 新增导航历史（后退/前进/上一级）、面包屑、地址栏回车跳转和收藏夹；每次跳转先验证挂载卷身份与根路径。
2. 文件列表增强：列头排序、过滤框、隐藏文件开关、文件大小/时间、文件/目录图标、右键“复制路径/属性/预览”。
3. 预览文本（txt/py/md/json/yaml/csv 等）及 PNG/JPG；显示编码、截断提示；大文本限定预览字节，二进制文件不强制按文本处理。
4. 对 Linux 大小写敏感路径、中文、空格、Unicode、Windows 长路径进行兼容测试。目录联接/符号链接不能无约束跳转至其他根。
5. 大目录枚举迁移到 worker+信号，保持选中文件与预览请求的代际一致性，旧结果不得覆盖新页面。
6. 从已经稳定的 `main.py` 中逐步抽离 `ui/` 模块，但不要一次性重构磁盘扫描、权限和适配器。
7. 统一界面空状态、错误提示、快捷键；坚持所有打开/预览动作只读。

## 5. 测试方法

- 使用临时目录生成中文名、空格名、大小写不同文件、空目录、无权限项、巨大文本、UTF-16 与 GB18030 样例。
- 测试返回/前进历史、卷卸载后旧路径失效、任务取消后 UI 不显示过期内容。
- Windows 实机在 C/D/E 只读浏览和预览，E: 测试文件内容应与上一步一致。

项目根目录的通用测试命令：

```powershell

```

新增测试需纳入统一 discovery；如果引入 `tests/` 包，确认 discover 能正确发现。

## 全任务统一安全要求

1. 严禁执行 `format`、`diskpart clean`、`Clear-Disk`、`Remove-Partition`、`Set-Partition`、`Set-Disk -IsOffline` 或任何修改分区表/EFI/Recovery/MSR 的命令；不直接开启 `\\.\PhysicalDrive0` 写句柄。
2. 默认禁止对 Ubuntu 分区 6 做任何文件创建、覆盖、删除、移动或属性修改；只有任务 08 在任务 07 实际通过、备份完成、明确授权且限定范围时才例外。
3. 对驱动、分区身份、权限或实际挂载模式存在疑问时，结果为 `UNKNOWN` 或 `READ_ONLY`，不推测具备写权限。
4. 除任务 05 在用户授权的 Windows 专用测试目录、任务 07 在独立可丢弃 ext4 测试介质、任务 08 在额外明确授权的 Ubuntu 专用测试目录外，真实磁盘只允许元数据查询和只读操作；自动化单元测试优先使用 `TemporaryDirectory` 或模拟适配器。
5. 不自动提升管理员权限；不能通过 `os.access`、磁盘类型、盘符、Windows 卷标志或人工关联推断 ext4 写入安全性。
6. 任何可能改变 Windows 文件的功能，必须在用户指定的测试目录中测试；禁止自动对真实个人文件进行 CRUD 测试。
7. 每次开发前检查 Git 状态并保留当前可用版本。若项目未初始化 Git，先征询用户或在项目目录内初始化；不得强制覆盖、重置或清理其未提交修改。
