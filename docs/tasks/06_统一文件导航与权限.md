# 任务 06｜跨文件系统统一路径和操作能力

> 建议一次 Claude Code 会话只完成此任务。  
> 前置条件：任务 05 已验收。  
> 本次交付：代码/测试/进度文档，不需要在此次会话提前开发后续功能。

## 一、任务目标

将 NativeWindowsBackend 与 Ext4ReadOnlyBackend 接入同一导航系统，统一路径、面包屑和操作权限。

## 二、必须实现的内容

1. 定义通用 `FileSystemBackend` 接口：`list_dir, stat, open_read, get_capabilities`；写接口在后续阶段再分层设计。
2. 定义内部路径 `VirtualPath(partition_id, path)`，每个后端负责将逻辑路径翻译为自身语义。
3. 面包屑、地址栏、后退/前进/向上都正确维护分区与内部路径；切换磁盘时不串目录。
4. 文件/目录展示统一字段：名称、大小、类型、修改时间、访问状态、后端来源，链接/权限不支持时显示“未知”而非伪造。
5. 能力判断使用统一 `CapabilityPolicy`：EFI、MSR、Recovery 等先按分类保护，再询问后端功能；未知/无挂载后端只能看分区信息。
6. 路径规范化要防止 `..` 越界、符号链接逸出沙箱，所有错误通过统一消息展示。
7. 耗时目录加载使用 worker + 取消；切换目录后不能展示已过时请求的返回结果。

## 三、交付文件与约束

- 不改变其他模块公共接口；如确实需要，记录迁移说明并修复调用者。
- **专门禁令：** 不要在此任务提前实现内置写入驱动或磁盘修改。

## 四、验收清单

- 同一界面在 `C:\Users` 与 Ubuntu `/home` 之间切换，无崩溃、无内容混淆。
- 对 EFI、Recovery、MSR 与未知分区显示不同说明，所有写按钮禁用。
- 对 Ubuntu 不允许通过地址栏和右键菜单启用写入。
- 模拟加载中切换分区，旧任务结果不会覆盖新列表。
