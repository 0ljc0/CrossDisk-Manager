# 任务 10｜Windows 原生分区的受控写入

> 建议一次 Claude Code 会话只完成此任务。  
> 前置条件：任务 09 已验收。  
> 本次交付：代码/测试/进度文档，不需要在此次会话提前开发后续功能。

## 一、任务目标

在 Windows 常规已挂载数据卷上开放新建、重命名、移动、删除、文本保存等功能。

## 二、必须实现的内容

1. 为 NativeWindowsBackend 增加经权限校验的 `create_dir, create_file, rename, move, delete, write_file` 等操作接口。
2. 写入前通过 `CapabilityPolicy` 检查：只允许正常数据卷；EFI、Recovery、MSR、未知、离线与加密锁定卷明确拒绝。
3. 文本编辑实现：打开原文件、保存修改、冲突检测（读取以来文件是否已被其他进程改动）、备份与临时文件原子替换（仅在适用同卷操作时）。
4. 删除先优先采用系统回收站支持的实现；永久删除必须二次确认，并明确不可恢复风险。
5. 新建/重命名/移动/覆盖提供路径冲突提示，不默默覆盖；遇到 ACL 权限拒绝不尝试绕过系统保护。
6. 加入撤销可能性说明：只有操作已实现可靠逆操作时才显示“撤销”，不能伪称所有删除可撤销。
7. 配置用户可写的测试目录，准备自动化功能测试；不得在 C:\Windows、引导分区和真实 Ubuntu 下跑写入用例。

## 三、交付文件与约束

- 修改/新增对应的 `app/` 模块，补充至少一个本阶段直接相关的 `tests/` 用例。
- 更新项目 `README.md`（运行方法变化时）和 `docs/PROGRESS.md`（本任务完成情况、下一步待办）。
- 不改变其他模块公共接口；如确实需要，记录迁移说明并修复调用者。
- **专门禁令：** 此任务仍禁止向真实 Ubuntu ext4 写入。

## 四、验收清单

- 使用 `D:\CrossDisk_TestWrite` 测试新建/保存/重命名/移动/删除，并核对结果。
- 在 UI 中选中 EFI、Recovery 和 Ubuntu 时写按钮不能执行；后端直接调用同样要拒绝。
- 模拟另一个进程修改文本，保存时显示冲突，不静默覆盖最新内容。
- 磁盘满、文件锁定、权限拒绝等异常不损坏原有文件。
