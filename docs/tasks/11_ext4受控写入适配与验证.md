# 任务 11｜ext4 写入后端准入评估与可选适配

> 建议一次 Claude Code 会话只完成此任务。  
> 前置条件：任务 10 已验收。  
> 本次交付：代码/测试/进度文档，不需要在此次会话提前开发后续功能。

## 一、任务目标

研究可行的成熟 ext4 写入后端；仅在符合全部准入门槛时启用受控写入。

## 二、必须实现的内容

1. 首先完成“可行性说明”：当前 Windows 系统盘与 Ubuntu ext4 同一物理盘，`wsl --mount` 不支持附加正在使用的 Windows 系统磁盘；不得使用系统盘离线规避。
2. 调查并列出候选成熟驱动/文件系统服务的名称、许可证、Windows 兼容性、ext4 特性支持、需要的权限、系统盘共存限制、真实支持哪些写入操作、是否有官方接口/API。
3. 定义 `Ext4WritableAdapter` 协议，但如果尚无已验证驱动，使用 `UnsupportedWriteBackend`，UI 写按钮保持禁用；不要用 `pytsk3` 或自行拼扇区实现写入。
4. 评估 ext4 journal、metadata checksums、64bit、case sensitivity、UID/GID、symlink、文件时间戳、写入同步及突然断电的一致性；不能只靠成功写入一个 txt 判断安全。
5. 仅在**可丢弃的 ext4 测试镜像或独立测试盘**上演示新增/修改/重命名/删除与 Linux 侧重新挂载校验；保存测试日志和限制说明。
6. 真实 Ubuntu 分区写入额外前提：可靠备份、用户明确选择读写模式、风险确认、驱动通过兼容性验证、只针对允许的用户数据目录（示例 `/home/ljc`）；禁止对系统路径写入。
7. 若缺少驱动/授权/兼容性证据，该任务的合格交付物是“安全禁用 + 可行性报告 + 可替换的写入适配接口”，而非冒险达成写入。

## 三、交付文件与约束

- 修改/新增对应的 `app/` 模块，补充至少一个本阶段直接相关的 `tests/` 用例。

- 不改变其他模块公共接口；如确实需要，记录迁移说明并修复调用者。
- **专门禁令：** 本任务不是承诺 ext4 必须可写；尊重驱动支持和安全验证的现实边界。

## 四、验收清单

- 在没有已验证 ext4 写入服务的环境里，程序正常运行且 ext4 明确显示“只读/未安装受控写入驱动”。
- 直接调用 ext4 写接口必须收到明确定义的“不支持写入”异常，而不是执行降级原始扇区修改。
- 具备隔离测试盘时，演示写入后由 Linux 原生 ext4 驱动校验，记录内核日志与完整性检查（在测试盘离线时执行）。
- 不要求、也不允许自动在用户当前 Ubuntu 真实系统分区写任何测试文件。
